# dsh-chat-recast（改问 / 换答）

DeepSeek Harness（DSH）插件：把一句发错的提问**改好重问**，或者对不满意的回答**换一种说法再答**。

## 为什么不是"原地改字"

DSH 的会话日志是只追加的，官方 Web 端只把「追加」事件渲染成消息气泡（`isAppendSurfaceEvent`）。
所以哪怕模型侧的上下文被改写，屏幕上那句「你郝」也不会变——官方 UI 也不会显示替换事件。
与其做一个"改了但看不见"的功能，这里用官方原语复刻 App 版的**效果**：

1. 找到这条回答对应的那条提问；
2. 在提问之前分叉（`sessionController.fork`）——新会话有自己的 Agent，历史截止到提问前；
3. 在新会话里用（修改后的）文字重新提问（`sessionController.prompt`）；
4. 把原标题去掉重复标题的数字后缀，命名给新会话（`sessionTitle.rename`）；
5. 把原会话移出列表（`workspaceRegistry.archiveSession`，归档可恢复，不从磁盘抹掉）。

## 用法

打开任意会话，在一条**已回答完**的回答下方，动作行里有三个图标（时间 / 复制 / 本插件）。

- **重新生成**：鼠标悬停第二个图标（旋转箭头），文字「重新生成」滑出；点击后同一提问再问一次。
- **修改**：悬停第三个图标（铅笔），显示「修改」；点击弹出一个**可拖动浮层**：
  - 按住顶部标题条可移动，拖右下角可改大小；
  - 改完点鲜蓝色的「确认修改」。

两个动作都会在侧边栏产生一个新会话（沿用原对话标题），并把原对话移出列表。
新会话是分叉出来的普通会话，可以继续聊、可以再次改问。

```
回答正文……
   ⟳ 重新生成     ✎ 修改          ← 回答下方动作行（图标；悬停出字）
   ┌───────────────────────────┐
   │ 修改提问 · 按住此条拖动  × │  ← 浮层：标题条拖动
   │ 你郝 …                    │  ← 文本域：右下角缩放
   │ [确认修改] [取消]          │
   └───────────────────────────┘
```

## 安装

1. 把本仓库放到任意本地目录（不要放进 DSH profile 内部）；
2. 打开 DSH → **插件** → **添加插件**，选择该目录（或在设置里用 Plugin Manager 安装本地目录）；
3. 无需构建：`package.json` 里已经声明 `dsh.bundle.patch` 与 `dsh.client`，Host 与浏览器两半都是纯 ESM/脚本。

## 限制与注意

- **只在会话空闲时可用**：正在回答的会话会拒绝操作（HTTP 409）。
- **提问必须是文字**：只有附件的提问暂不支持改写。
- **原对话是"归档"不是"销毁"**：在归档列表里可以恢复；每次操作的记录写在
  `<DSH_HOME>/chat-recast/history.jsonl`（源会话、子会话、标题、是否归档成功）。
- **界面不会自动跳到新会话**：DSH 没有向插件开放"打开某个会话"的入口，请从侧边栏点开新会话。
- **工具调用会重放**：分叉复制的是提问之前的完整历史，重新提问后模型可能再次调用工具，
  可能产生新的时间/费用开销。
- **没有"回答上方"的挂载点**：DSH 的 `assistant-step` 直接渲染 markdown，只对外暴露推理块与消息图片两个子槽；
  本插件把入口放在官方的回答动作行（回答下方），这是唯一合法的位置。
- **接口**：`GET/POST /dsh-chat-recast/api` 监听本机 localhost，与其它插件接口同形；无额外鉴权。

## 兼容性

在 DSH `0.2.2-rc.5`（Windows 桌面版）上验证：分叉、重问、改名、归档四条链路均跑通。
插件依赖 DSH 的服务契约（`sessionController` / `sessionTitle` / `workspaceRegistry` / `sessions` / `agents`），
升级 DSH 后若这些契约变化，插件可能需要在 `lib/index.js` 里跟进。
